# EverTruck Database Service (`/database`)

This service manages the MySQL 8.0 relational database for EverTruck Logistics. It is responsible for storing all core platform data, including user accounts, fleet inventory, drivers, shipments, real-time tracking events, invoices, and blog content.

---

## Directory Structure

```
database/
├── init.sql        # Initialization script run automatically on first container startup
├── migrations/     # SQL migration files generated by Drizzle ORM
└── backups/        # Scripts and documentation for database backups and point-in-time recovery
```

---

## Architecture & Docker Configuration

In `docker-compose.yml`, the database service is defined as `evertruck-mysql`:
- **Image**: `mysql:8.0` (official stable MySQL release)
- **Port**: `3306` (accessible exclusively within `evertruck-network`)
- **Persistent Volume**: `mysql_data` mounted to `/var/lib/mysql`
- **Initialization**: `./database/init.sql` mounted read-only to `/docker-entrypoint-initdb.d/init.sql`

> [!IMPORTANT]
> **Security Rule**: The MySQL container is **never** exposed publicly to the host machine or external internet. It communicates strictly over the private Docker network (`evertruck-network`) with the Backend API service.

## Database Schema & Migrations

The database schema is defined programmatically in TypeScript using **Drizzle ORM** inside the backend service (`/backend/db/schema.ts`).

### Generating Migrations
When you modify tables or fields in `/backend/db/schema.ts`, generate a new SQL migration file into `/database/migrations/` by running:

```bash
# From inside the backend container or locally
cd backend
npx drizzle-kit generate
```

### Applying Migrations
Migrations are applied automatically or manually via Drizzle Kit:

```bash
# Push migrations directly to the database
npx drizzle-kit migrate
```

---

## Persistent Storage & Volumes

All MySQL data files, write-ahead logs, and schema metadata are stored in a Docker named volume called `mysql_data` (`evertruck-mysql-data` in Docker Compose).

- **Surviving Container Restarts**: Because data resides in a named volume outside the container filesystem, restarting, stopping, or updating the container will **not** result in data loss.
- **Inspecting Volume Data**:
  ```bash
  docker volume inspect evertruck-mysql-data
  ```

## Connecting & Troubleshooting

### Executing an Interactive MySQL Shell
To connect directly to the database inside the running Docker container:

```bash
docker compose exec mysql mysql -u evertruck -psecurepassword123 evertruck_db
```

### Useful SQL Commands Inside MySQL:
```sql
-- List all database tables
SHOW TABLES;

-- Describe the shipments table structure
DESCRIBE shipments;

-- Check current active connections
SHOW PROCESSLIST;
```

### Resetting the Database (Development Only)
If you need to wipe all local data and re-initialize from scratch:

```bash
# CAUTION: This deletes all data permanently!
docker compose down -v
docker compose up --build -d
```
